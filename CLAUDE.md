# terraform-provider-orchestra — Agent Instructions

## Project Overview

This is the **Terraform provider for Orchestra**, a Go module built on the
[Terraform Plugin Framework](https://developer.hashicorp.com/terraform/plugin/framework). It manages Orchestra
pipelines and environments through the Orchestra REST API.

Build with `make build`, test with `make test`, vet with `make vet`, format with `make format`, regenerate
reference docs with `make docs`, and refresh the spec with `make openapi`. `make help` lists them all.

> This file previously contained the agent guide for the Mintlify documentation site
> (`orchestra-hq/orchestra-docs`). Its rules — `.mdx` only, `docs.json` navigation, Mintlify components — do not
> apply here and actively conflict with this repo, where `docs/` is `.md` generated by `tfplugindocs`.

## Source of Truth: the OpenAPI spec

Everything the provider talks to is described by two Orchestra OpenAPI specs, each with its own base URL:

- **`https://docs.getorchestra.io/api/engine.yaml`**, the Engine API (committed as `internal/apicontract/engine.yaml`)
- **`https://docs.getorchestra.io/api/agents.yaml`**, the Agents API (committed as `internal/apicontract/agents.yaml`). Code
  that calls it lives under `internal/agents/`; the contract tests check calls from there against this spec.

Before adding or changing anything that calls the API, read the spec. Do not infer endpoints, parameter names or
response shapes from the existing Go code — it has been wrong before. Three of the provider's five pipeline calls
once targeted endpoints that did not exist, and one of those failed silently.

### Workflow for an API-facing change

1. **Refresh and read the spec.**

   ```bash
   make spec-drift   # read-only: what changed in the live specs since the committed ones
   make openapi      # refreshes both committed specs, regenerates internal/enums
   ```

   A weekly workflow opens a **Spec sync** PR with that report. Decide each item with the
   `spec-sync` skill, and classify any endpoint you choose not to implement, or request-body property you
   choose not to send, in `internal/apicontract/coverage.yaml`.

   Check the exact path, method, query parameters, request body schema and response schema. Watch for:
   - list endpoints that return a bare array versus a `{page, pageSize, total, results}` envelope,
   - selectors that live in the query string (`DELETE /pipelines`) versus the body (`PUT /pipelines`),
   - `camelCase` JSON property names — the response structs must match exactly,
   - `additionalProperties: true` and `anyOf`/`oneOf`, which have no direct Terraform equivalent.

2. **Update `internal/apicontract/contract_test.go`.** Add the `(method, path)` and every query parameter you
   send. This test is the guard-rail for the whole class of bug above; a change that skips it is incomplete.

3. **Implement**, then run `go build ./... && go vet ./... && go test ./...`.

4. **Regenerate docs** with `make docs` if any schema changed. `docs/` is copied from `examples/`, so a stale
   example becomes published documentation that does not apply; `internal/provider` runs `terraform validate`
   over them as part of `go test ./...`.

### Useful commands for reading the spec

```bash
# Every operation, with its tags.
python3 -c "
import yaml; s=yaml.safe_load(open('internal/apicontract/engine.yaml'))
for p,i in s['paths'].items():
    for m,o in i.items():
        if m in ('get','post','put','patch','delete'):
            print(f'{m.upper():6} {p:55} {o.get(\"summary\")}')
"

# One schema's properties.
python3 -c "
import yaml,json; s=yaml.safe_load(open('internal/apicontract/engine.yaml'))
d=s['components']['schemas']['PipelineModel']
print('required:', d.get('required'))
for k,v in d['properties'].items(): print(f'  {k:24}', json.dumps(v)[:140])
"
```

## Layout

|---|---|
| `internal/client/` | HTTP client: auth, headers, retries, 404 detection, pagination |
| `internal/provider/` | Provider schema, configuration, resource and data source registration; tests that every type has an example and that `examples/` pass `terraform validate` |
| `internal/resources/<name>/` | One package per resource |
| `internal/agents/` | Agent and skill resources and the skills data source: everything that calls the Agents API |

| `internal/tfconv/` | Shared API-JSON ↔ Terraform value conversion |
| `internal/apicontract/` | The committed specs (`engine.yaml`, `agents.yaml`) and tests asserting the provider matches them, in both directions |
| `internal/apicontract/coverage.yaml` | Every endpoint the provider deliberately leaves alone, and every property it leaves out of a request body it sends, and why. A spec operation neither called nor listed, or a written property neither sent nor listed, fails `go test` |
| `tools/specdrift/` | `make spec-drift`: structural diff of two specs, run weekly by `.github/workflows/spec-sync.yml` |

| `internal/resources/rsapply/` | Tests driving resources through plan/apply against a stub API |
| `internal/datasources/dsread/` | Tests driving every data source against a stub API |
| `internal/acctest/` | Acceptance tests against a live workspace, skipped without a key |
| `examples/` | Consumed by `tfplugindocs`; every resource and data source needs one |
| `docs/` | Generated by `tfplugindocs` — never edit by hand |
| `templates/guides/` | Registry guides that `tfplugindocs` renders into `docs/guides/`; their configurations live in `examples/guides/` |

## Conventions

### Generated versus hand-written

`internal/enums/enums_gen.go` is the only generated file, written by `internal/enums/gen.go` (`make enums`).
Everything else — every schema, model, wire struct and converter — is hand-written.

Do not reintroduce schema codegen. `tfplugingen-openapi` renders a union and an `additionalProperties: true`
object as an *empty* object, producing attributes that can never hold a value; that is exactly how
`orchestra_pipeline.data` once shipped as an attribute nothing could be written to. The four-stage pipeline that
produced it (`generator_config.yml`, `provider_code_spec.json`, two scripts under `scripts/` and a CI workflow)
was removed deliberately. If you are tempted to generate a schema from the spec, write it by hand instead.

Any move towards generating more keeps one non-negotiable rule: a generator fails on a spec shape it cannot map;
it never emits a placeholder.

### Modelling the API in Terraform

- **Free-form objects** (`additionalProperties: true`, untyped `any`) → `jsontypes.NormalizedType{}` string
  attributes. Say so in the description and point at `jsonencode({...})`.
- **Unions** → separate sibling attributes, merged on the wire and split on read. Reject ambiguity in
  `ValidateConfig` rather than guessing.
- **`string | integer`** → a `types.String` that accepts both, converted when encoding.
- **Enums** → `stringvalidator.OneOf(enums.X...)` from `internal/enums`, never a hand-typed list.

### Resource behaviour

Every resource must:

- read from `req.Plan` in `Create`/`Update`, never `req.Config` — the config has no defaults or computed values
  applied, which produces "Provider produced inconsistent result after apply";
- populate state from the create/update **response** rather than issuing a follow-up read;
- map `client.ErrNotFound` in `Read` to `resp.State.RemoveResource(ctx)`;
- implement `ImportState`;
- mark an attribute `RequiresReplace` when the API's patch endpoint does not accept it.

### Errors and descriptions

- Diagnostics: a short summary and a detail that says what to do. Attach a `path.Path` when the problem is an
  attribute.
- Every attribute needs a `Description`. Add `MarkdownDescription` when backticks or a link help.
- Prefer prose that names the API constraint behind a rule, so the next reader knows it is not arbitrary.

### Comments

Explain **why**, not what. Reach for a comment where the code encodes a non-obvious API constraint — a reserved
attribute name, a required-but-empty field, a union with no discriminator. Do not narrate ordinary Go.

## What Not To Do

- Don't edit `docs/` or `internal/enums/enums_gen.go` by hand
- Don't add an endpoint call without a matching entry in `internal/apicontract/contract_test.go`; the test scans
  `internal/` for call sites, so an unlisted one fails the build rather than failing silently in production
- Don't leave a property out of a request body without listing it under `properties` in `coverage.yaml`. A PUT
  replaces the whole object, so an unsent property resets what the Orchestra UI set: `orchestra_monitor` cleared
  `subscribers` on every apply. `TestEveryWrittenPropertyIsClassified` reads a wire struct's JSON tags, so a new
  one that its package's `WireSchemas` cannot reach must be added there
- Don't let a stub return a shape the real API never produces. The API fills in declared defaults on the way out
  (`webhook` → `{"enabled": false}`, `dependsOn` → `[]`, a task's `name` → `""`, an anomaly's numerics), and a
  stub that echoes the request verbatim hides every resulting apply failure. See `applyServerDefaults`.
- Don't trust a default declared in the spec. `minBaselineSeconds` is documented as `0`; the API returns `10`.
  Mark such attributes `Computed` rather than giving them a client-side `Default`.
- Don't put an API error body straight into a diagnostic without going through the client. A FastAPI 422 echoes
  the request payload, and diagnostics are never redacted — `redactErrorBody` strips it.
- Don't hand-maintain an enum list that the spec already defines
- Don't read `req.Config` in `Create` or `Update`
- Don't expose run telemetry (pipeline runs, task runs, logs, incidents) as Terraform state
- Don't use `connection` as a root attribute name — Terraform reserves it
- Don't commit a spec you have not regenerated the enums and docs from
